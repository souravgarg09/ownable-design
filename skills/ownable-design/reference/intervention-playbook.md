# Intervention playbook

Load this for active redesign, improvement, fix, polish, or transformation work.

When tool/media choice matters, also load [capability-routing.md](capability-routing.md). When media is important, load [media-strategy.md](media-strategy.md).

## 1. Preserve the authorized visual authority

Before changing anything, confirm the scope mode:

- refine/extend → preserve incumbent identity and system unless a specific part is authorized to change;
- replace/new → a new visual world may be established.

Do not smuggle redesign into polish.

## 2. Default loop

**Understand → inspect → diagnose → prioritize → execute → re-render/inspect → finish**

- understand truth, scope, existing system, assets, content, and constraints;
- inspect the real experience when visual evidence exists;
- diagnose root causes rather than collecting cosmetic complaints;
- prioritize the highest-impact causes;
- execute justified changes;
- re-render/re-inspect after material changes;
- fix remaining material issues in one bounded pass;
- stop.

When Impeccable is active, use its current refinement/redesign and verification mechanics.

## 3. Root-cause diagnosis

A visible defect may originate in:
- wrong surface/section purpose;
- weak or redundant content;
- wrong sequence/hierarchy;
- missing proof;
- wrong representation;
- weak media;
- generic composition;
- identity drift;
- under/over-resolved motion;
- responsive mismatch;
- implementation failure.

Fix the cause at the narrowest correct level.

## 4. Structural intervention ladder

For each major structural unit:

1. **keep** — role and structure are right;
2. **refine** — role is right, hierarchy/composition is weak;
3. **regroup/reorder** — sequence or priority is wrong;
4. **merge** — multiple units do the same job;
5. **split** — one unit contains genuinely different jobs;
6. **replace** — the concept/shell itself is wrong;
7. **remove** — optional unit earns no meaningful role.

Required content/functionality remains protected.

## 5. Medium intervention ladder

For any expressive medium:

**keep → refine → transform → replace → add → simplify → remove**

Apply to typography, color/material, content framing, media, illustration, iconography, diagrams, data viz, motion, interaction, video, 3D, sound, backgrounds, proof presentation, and responsive treatment.

Choose the least destructive intervention that actually solves the cause.

## 6. Asset intervention ladder

For important media:

**keep → reframe → edit/transform → replace with stronger verified real media → generate/authored media → remove**

Skip directly to the correct step when obvious. The ladder is not bureaucracy.

## 7. Motion intervention

Ownable decides:
- whether motion belongs;
- what element should move;
- what conceptual job it serves;
- whether to keep, retarget, simplify, replace, add, or remove it.

Do not preserve a technically impressive animation that weakens clarity, credibility, task flow, or the chosen world.

When Emil is active, defer detailed motion craft to it.

## 8. Responsive intervention

Do not merely stack desktop.

Possible changes include:
- crop/source changes;
- media substitution;
- simplified sequence;
- reordered proof/action;
- reduced atmosphere;
- alternate interaction model;
- focused detail;
- alternate signature moment.

Preserve required content/functionality and identity.

## 9. Whole-experience check

A local improvement fails if it causes:
- perceptual repetition;
- visual imbalance;
- broken pacing;
- media-language drift;
- inconsistent identity;
- competing focal points;
- weakened proof;
- weaker task clarity.

Judge interventions in the full experience.

## 10. Capability honesty

If a needed capability is unavailable:

1. look for another capability that performs the same role;
2. choose an honest alternate medium if possible;
3. continue every useful intervention that remains possible;
4. state only the materially blocked part.

Do not hand work back to the user when the active environment can safely complete it.
