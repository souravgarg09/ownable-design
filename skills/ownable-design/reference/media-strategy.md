# Media strategy

Load this whenever imagery, illustration, generated media, documentary proof, cutouts, diagrams, video, 3D, textures, or other visual media materially affects the design.

The goal is not “more imagery.” The goal is the **right media, with the right truth status, in the right role**.

## 1. Classify the media role first

For every important media moment, decide what job it performs:

- **documentary proof** — real person, product, place, facility, event, result, craft, credential, or evidence;
- **subject artifact** — real object/document/process detail that carries identity;
- **explanatory** — diagram, process visualization, annotated image, comparison, map, chart;
- **editorial/atmospheric** — authored image used for tone, metaphor, narrative, or visual world;
- **interface/product representation** — UI, device, product mechanism, configurable state;
- **material/environmental** — texture, surface, background, spatial layer;
- **decorative** — no information/identity role; treat with suspicion.

If the role is unclear, the media probably does not earn the space.

## 2. Choose the production mode

For each important media moment choose one:

1. **use verified real media**;
2. **edit/transform verified real media**;
3. **generate/authored media**;
4. **construct semantically** with code/vector/diagram/data;
5. **remove / use no media**.

Do not regenerate reality because editing or sourcing is less convenient.

## 3. Proof-sensitive rule

Use verified real media when authenticity is the reason the visual matters.

Examples: real founder/artist/doctor, actual building/store/facility, real product finish, real before/after, real event, real credentials, real craft output.

Generated imagery may support atmosphere or explanation but must not impersonate proof.

Web visibility does not equal reuse permission. Prefer first-party, owned, licensed, public-domain, or user-approved production sources.

## 4. Asset role brief

Before producing a major generated/edited asset, define:

- role in the page;
- subject;
- truth class (proof / illustrative / explanatory);
- composition and focal area;
- crop/aspect ratio;
- background behavior;
- transparency/alpha requirement;
- medium/style;
- relationship to the chosen visual world;
- responsive variants if needed;
- what must **not** be invented or altered.

The generation prompt should follow this brief instead of asking for generic “premium” imagery.

## 5. Produce critical assets before locking layout

If the hero, signature moment, major composition, or section geometry depends on a specific asset, produce and inspect that asset **before** finalizing the layout around a placeholder.

Do not design a page around imaginary media and then accept a weak final asset because the code is already built.

## 6. Real-asset editing authority

When editing is the right move, Ownable may use available capabilities to:

- remove backgrounds / create real alpha cutouts;
- mask/isolate subjects;
- clean clutter/distractions;
- correct exposure/white balance/color;
- relight without falsifying proof;
- reframe/extend composition;
- correct perspective;
- remove irrelevant objects;
- clean/replace backgrounds;
- composite truthful elements;
- upscale/recover detail;
- create landscape/portrait/mobile/desktop variants.

For organic contours, prefer actual matting/cutout to fake geometric clipping.

## 7. Generated-media authority

When generation is truthful and conceptually better, Ownable may create:

- photographic campaign/supporting imagery;
- watercolor / gouache;
- pencil / charcoal / ink / line work;
- etching / engraving;
- collage / mixed media;
- textured editorial illustration;
- diagrammatic illustration;
- material studies / textures;
- stylized 3D;
- other subject-appropriate media.

Generation is not a quota. Do not create filler simply because the tool exists.

## 8. Explanatory media must explain

Charts, maps, timelines, diagrams, process graphics, comparisons, and annotated visuals should make a real relationship easier to understand.

Never invent data, precision, geography, causality, sequence, or relationships for visual sophistication.

Use semantic/vector/data construction when the content must remain exact, responsive, selectable, or interactive.

## 9. Transparency and edge integrity

For cutouts/background removal:

- require real transparency/alpha when the layout needs it;
- preserve fine edges, hair/fibers, internal holes, and white foreground details;
- do not mistake white/checkerboard-looking pixels for actual alpha;
- inspect on both light and dark intended surfaces when edge quality matters.

If one generator cannot provide the required alpha, route to another available matting/editing capability.

## 10. Responsive media art direction

Responsive treatment may use:
- different crop;
- different source image;
- portrait/landscape variant;
- simplified sequence;
- still instead of video/3D;
- focused detail instead of full scene;
- reduced atmospheric layer.

Do not let mobile inherit a broken desktop crop merely for consistency.

## 11. Repetition discipline

Audit perception, not filenames.

Two different files can still feel repetitive if they show the same pose, crop, angle, subject, texture, or visual idea.

Keep primary campaign media privileged. Reuse only when the repetition is a deliberate callback or a materially different role.

## 12. Validate in context

A tool success state is not approval.

Inspect the actual output for:
- correct subject/semantics;
- composition/crop;
- edge quality;
- transparency;
- artifacts/text corruption;
- visual-world coherence;
- truth boundary;
- resolution/performance suitability;
- placement and scale in the real layout.

Reject, regenerate, edit, or remove weak media.
