# Standalone quality floor

Load this only for specialist domains that are **not already covered** by active companion skills.

Ownable is an art-direction skill, but it should still produce usable work when Taste, Impeccable, or Emil are unavailable.

This is a compact fallback, not a replacement for those specialists.

## 1. Context fit before visual ambition

Identify:
- user/audience;
- primary task or desired action;
- content type;
- surface intent;
- brand/product constraints;
- supported contexts and input modes;
- important truth/proof;
- what would make a visually impressive result unusable.

A beautiful design that obscures the task, damages trust, or fails the real use context is not a successful Ownable result.

## 2. Commit to one coherent system

After choosing a direction, establish:
- a clear visual thesis;
- deliberate typography;
- a coherent palette/light strategy;
- material/surface behavior;
- spacing/rhythm;
- image/illustration language;
- information representation;
- interaction thesis when needed.

Do not make every section a new aesthetic experiment.

## 3. Typography is an active design material

Choose type deliberately rather than using the same default family on every project.

Use hierarchy, scale, width, weight, spacing, and line length to support content and personality.

Avoid typographic costume: monospace does not automatically mean technical, serif does not automatically mean luxury, and all-caps tracking does not automatically mean editorial.

## 4. Use containers and cards only when they have a job

A card should group, contain, compare, or support interaction.

Do not chop a page into identical rounded rectangles simply because components are easy to build.

Let hierarchy and content shape the container grammar.

## 5. Functional and accessibility floor

For interactive work:
- primary actions must work;
- keyboard/focus behavior must remain usable;
- essential information must not depend on hover alone;
- contrast and legibility must be credible;
- touch targets must be reasonable;
- reduced-motion preferences must be respected;
- required loading/empty/error/disabled/success states should exist when the product can encounter them.

When a dedicated accessibility/product skill is active, defer to it.

## 6. Responsive behavior is designed, not patched

Test representative widths and input modes when rendering is available.

Do not assume stacking is enough. Re-art-direct media, hierarchy, sequence, and interactions where needed while keeping the same identity.

## 7. Motion fallback

If Emil is unavailable:
- animate only when there is a clear purpose;
- keep motion bounded and interruptible where possible;
- avoid identical entrance animation on every section;
- preserve readable content without waiting for animation;
- provide reduced-motion behavior.

Do not invent a detailed motion system inside Ownable.

## 8. Anti-default fallback

If Taste is unavailable, check that the work did not drift into a familiar generated-page fingerprint simply because it was convenient.

Look for repeated AI habits such as:
- generic gradient/mesh hero;
- floating pill navigation without rationale;
- same-size feature cards;
- decorative glass everywhere;
- category-default dark/light palette;
- monospace-as-tech;
- meaningless eyebrow labels;
- decorative metrics;
- repeated marquee or fade-up choreography;
- stock-like generated imagery that says nothing specific.

Any of these can be correct when the brief earns them. The problem is unexamined default use.

## 9. Verification fallback

If Impeccable is unavailable and rendering exists:
1. build the complete requested scope;
2. inspect representative desktop/mobile or relevant device contexts in one bounded round;
3. fix the material issues found;
4. confirm once;
5. stop.

Do not endlessly polish.

## 10. Honest finish

Report what was actually changed and verified.

Name unresolved limitations only when they materially affect the result.
