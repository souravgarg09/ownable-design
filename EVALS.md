# Ownable behavioral evals

These evals are for testing agent behavior after rule changes. They are not design templates.

A change should improve these cases without creating a new universal visual default.

## E1 — Category cliché resistance

**Prompt:** Design a premium jewellery website for a regional jeweller with real store/building/product photography.

**Pass behavior:**
- does not jump automatically to black + gold + serif + glass;
- mines actual brand/store/product/material evidence;
- preserves verified photography as proof;
- produces a subject-specific direction contract;
- uses the logo-swap test.

## E2 — Refinement does not become redesign

**Prompt:** Polish an established SaaS settings page. Preserve its existing design system.

**Pass behavior:**
- classifies as refine/extend;
- preserves visual authority and interaction model;
- fixes hierarchy/states/responsive defects without inventing a new brand world.

## E3 — Missing hero media

**Prompt:** Build an artist homepage whose concept depends on a hand-drawn rain-and-tape illustration. Image generation is available.

**Pass behavior:**
- identifies the media as authored/editorial, not proof;
- generates/inspects the critical asset before locking final hero composition;
- does not stop at suggesting a prompt;
- validates the final asset in the rendered layout.

## E4 — Transparent cutout

**Prompt:** Use the supplied real product photo as a floating cutout over a textured background.

**Pass behavior:**
- edits the real photo instead of regenerating the product;
- creates real alpha transparency when capability exists;
- checks edges/holes on the intended background;
- does not fake organic contours with CSS circles/polygons.

## E5 — Proof versus atmosphere

**Prompt:** Build a hospital site with limited real facility/doctor photos and permission to generate supporting visuals.

**Pass behavior:**
- keeps real doctor/facility imagery for proof-sensitive moments;
- generated media is clearly illustrative/explanatory/atmospheric;
- no fabricated medical outcomes, equipment, credentials, or facilities.

## E6 — Wrong representation

**Prompt:** Explain a five-step industrial inspection process on a landing page.

**Pass behavior:**
- considers sequence/diagram/interactive explainer instead of default feature cards;
- does not invent measurements/relationships;
- representation follows information.

## E7 — First viewport thesis

**Prompt:** Build a marketing homepage for a robotic inspection product.

**Pass behavior:**
- opening demonstrates the product/mechanism or proof rather than generic “future of AI” mood;
- user knows what it is, why it matters, and what to do quickly;
- avoids default neon-AI language unless evidence/brief earns it.

## E8 — Cross-project fingerprint

**Prompt:** In sequence, design sites for a folk artist, jeweller, hospital, lodge, and B2B robotics company.

**Pass behavior:**
- does not repeat the same hero/nav/card/type/palette/motion grammar by habit;
- shares quality standards, not recognizable surface identity.

## E9 — Motion restraint

**Prompt:** Add motion to a frequently used operational dashboard.

**Pass behavior:**
- questions whether motion is needed;
- uses motion for state/feedback/continuity rather than spectacle;
- defers mechanics to Emil when present.

## E10 — Capability portability

**Prompt:** Improve a site in an environment with image editing and rendering but no preferred image generator.

**Pass behavior:**
- inventories capabilities rather than assuming failure;
- edits/sources/constructs media as appropriate;
- core reasoning remains provider-neutral.

## E11 — Cultural specificity

**Prompt:** Build a contemporary Kutch textile atelier site.

**Pass behavior:**
- uses verified material/process/place/craft evidence;
- avoids generic “heritage India” costume;
- cultural cues have a semantic relationship to the atelier.

## E12 — Direction commitment

**Prompt:** After approving a bold archival-editorial direction, implement the full site.

**Pass behavior:**
- does not average the approved world back into generic premium components;
- quieter regions still inherit the same grammar;
- responsive adaptation preserves identity without literal desktop shrinkage.
